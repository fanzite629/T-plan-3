## 执行门槛

- 等根代理明确运行文件冻结、批准的预览 URL、Windows 包路径和原生自动化合同后，才启动浏览器或软件。测试不得下载、安装依赖或启动自己的预览服务。
- 历史 `file://` 导航限制继续有效，不运行旧脚本的文件地址，也不以另一浏览器绕过限制。HTTP 验收只接收根代理提供的 `127.0.0.1` 白名单地址；原生软件使用明确批准的本地虚拟 HTTPS 内容源。
- 所有数据使用合成验收数据。浏览器用新 context，原生软件必须有隔离测试 profile 参数；不读写现有用户浏览器、WebView2 profile 或系统剪贴板内容。
- 保留历史报告、脚本和证据。新增脚本仅 `tests/tplan-*`；输出仅 `tests/desktop-evidence/`；最终报告 `T计划_桌面与UI验收.md`。

## 原生 Windows 包专项

| 编号 | 实际路径与主要判据 | 必须区分的边界 |
| --- | --- | --- |
| W1 | 从隔离解压目录直接启动真实 EXE，出现名为 T计划的独立原生窗口；记录 EXE、窗口和子进程身份 | WebView2 子进程允许；不得把 Edge --app 或新 Chrome/Edge 浏览器窗口当成原生封装 |
| W2 | 默认启动不启用调试参数；检查应用自身及子进程监听端口，不依赖本机 HTTP 服务 | 调试模式 CDP 监听需单独标注，不与默认启动检查混淆 |
| W3 | 通过批准的原生虚拟 HTTPS 地址观察资源与请求；关闭外部网络后验证可用范围 | 不使用 file 导航；外部请求与虚拟源本地资源分开；若只测已加载断网，不声称断网首次启动 |
| W4 | 在隔离 profile 通过真实 UI 保存合成数据，正常关闭并重新启动同一包；所有字段一致 | 不靠同一进程未退出伪装重启，不使用用户实际 profile |
| W5 | 原生 UI JSON 导出、清空、导入以及坏 JSON 拒绝；schema 2 旧备份迁移 | Web 浏览器旧存储不会假称自动迁移到新原生 profile；以显式 JSON 导入验证 |
| W6 | 将同一发行包复制/重新解压到另一隔离目录，使用同一测试 profile 再启动，原数据完整 | 移动的是软件文件，不是用户数据；验证稳定 profile 路径与内容 origin |
| W7 | 包内文件清单与内容抽查，无 localStorage、profile、历史 JSON、个人 PDF/截图、测试证据或用户记录 | 运行必需资源允许，合成数据只在包外隔离 profile |
| W8 | 交付源文件/单文件/Windows 包版本一致，核心数据文件未改；软件窗口退出后只结束本轮创建的测试子进程 | 记录最终 SHA256 与实际运行对象；不关闭用户自己的浏览器或程序 |

需根代理提供：最终 EXE/ZIP 与封装源码路径、虚拟 HTTPS origin、默认数据目录、隔离 profile 参数、仅测试时启用的自动化/CDP 参数、正常退出方式、已安装 WebView2 运行时要求。未满足的项目记录 NOT RUN/NOT VERIFIED，不能以其他层面 PASS 替代。
